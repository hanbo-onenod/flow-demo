## Goal

`tests/test_export.py::test_order_numbers_are_unique` fails now and then (`assert 300 == 299`) because `app/db.py::make_order_numbers` draws order numbers with replacement and sometimes returns duplicates. It broke CI on T-001 (PR #11) and T-002 (PR #28) for reasons unrelated to those changes, made a person re-run CI each time, and made the T-002 acceptance draft (PR #29) read "not met". Make `make_order_numbers` always return unique order numbers so the test passes every time.

## Scope

- In: `app/db.py::make_order_numbers` returns `n` distinct order numbers for any `n` and any `random.Random`.
- Out: the test itself stays as it is (its assertion and the `FLOW_DEMO_FLAKY_RATE` forced-failure hook for the circuit-breaker drill are kept); no change to the CSV export code, its columns or encoding; no other tests or reports. Seeded order numbers may change as a side effect; that is acceptable as long as all existing tests and the export benchmark still pass.

## Acceptance criteria

- Full `pytest` passes 50 runs in a row: `for i in $(seq 50); do pytest -q || exit 1; done` exits 0.
- `make_order_numbers` never returns duplicates across 10,000 seeds for n=300: `python -c "import random; from app import db; assert all(len(set(db.make_order_numbers(300, random.Random(s)))) == 300 for s in range(10000))"` exits 0.
- The circuit-breaker drill still works: `FLOW_DEMO_FLAKY_RATE=1 pytest -q tests/test_export.py::test_order_numbers_are_unique` fails with the forced-failure message.
- Exporting 10,000 orders still takes under 1 second (`python scripts/bench_export.py`).
