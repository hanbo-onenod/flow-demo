## Goal

Users want to export only the orders from a chosen period instead of the whole order table (PRD "Export enhancements", paragraph 2). Add an optional, inclusive start and end date to the order report export, on both the command line and the `export_csv` function, with a clear error for invalid input instead of an empty file.

## Scope

- In: `python -m app.export_report out.csv` gains optional `--start YYYY-MM-DD` and `--end YYYY-MM-DD`. `app.export_report.export_csv(conn, path, start=None, end=None)` gains the same two optional arguments. Only orders whose `order_date` is on or after `start` and on or before `end` are exported (both ends inclusive). Either end may be given alone: only `start` means from that day to the latest order, only `end` means from the first order to that day.
- In: only ISO `YYYY-MM-DD` dates that exist in the calendar are valid. Anything else (for example `2026/03/01`, `2026-3-1`, `2026-02-30`, `abc`) is an invalid date. A start later than the end is an invalid range. For an invalid date or range the command prints a clear error that names the bad value and the expected format `YYYY-MM-DD` (or says the start is after the end), exits with a non-zero code, and does not create or overwrite the output file. The function raises `ValueError` with the same message and does not create or overwrite the file.
- In: a valid range with no matching orders is not an error: the command exits 0 and writes a CSV with the UTF-8 BOM and only the header row.
- In: tests in `tests/test_export.py` for the cases above.
- Out: with no `--start`/`--end` (and no `start`/`end` arguments) the output stays byte-for-byte as today. No change to the columns, row order, encoding (UTF-8 BOM) or `--db` option. No other PRD items (for example Excel export), no change to `app/db.py` seeding, no other date formats, no time-of-day filtering.

## Acceptance criteria

All commands run from the repository root with `FLOW_DEMO_FLAKY_RATE` unset. The default demo DB (no `--db`) is seeded with 10,000 orders dated 2026-01-01 to 2026-10-27, about ten months.

- One month out of ten returns exactly that month's orders, from the command line: `rm -f /tmp/t004-mar.csv && python -m app.export_report /tmp/t004-mar.csv --start 2026-03-01 --end 2026-03-31 && python -c "import csv; from app import db; c=db.connect(); db.seed(c); want=[r[0] for r in c.execute(\"SELECT order_no FROM orders WHERE order_date BETWEEN '2026-03-01' AND '2026-03-31' ORDER BY order_date, order_no\")]; rows=list(csv.reader(open('/tmp/t004-mar.csv', encoding='utf-8-sig'))); assert rows[0]==['order_no','order_date','customer','city','amount']; got=[int(r[0]) for r in rows[1:]]; assert want and got==want, (len(got), len(want)); assert all(r[1].startswith('2026-03') for r in rows[1:])"` exits 0.
- The same through the function: `python -c "import csv; from app import db; from app.export_report import export_csv; c=db.connect(); db.seed(c); n=export_csv(c, '/tmp/t004-fn.csv', start='2026-03-01', end='2026-03-31'); want=c.execute(\"SELECT COUNT(*) FROM orders WHERE order_date BETWEEN '2026-03-01' AND '2026-03-31'\").fetchone()[0]; rows=list(csv.reader(open('/tmp/t004-fn.csv', encoding='utf-8-sig')))[1:]; assert want and n==want==len(rows)"` exits 0. `start` and `end` may be passed as `YYYY-MM-DD` strings (accepting `datetime.date` too is allowed).
- Both ends are inclusive: `--start 2026-03-15 --end 2026-03-15` exports exactly the orders dated 2026-03-15 (a test in `tests/test_export.py` checks the count against `SELECT COUNT(*) FROM orders WHERE order_date = '2026-03-15'` and that it is greater than 0).
- One-sided ranges work: `--start 2026-10-01` alone exports exactly the orders with `order_date >= '2026-10-01'`, and `--end 2026-01-31` alone exports exactly the orders with `order_date <= '2026-01-31'` (tests compare against the same SQL counts).
- No range behaves as today: `python -m app.export_report /tmp/t004-all.csv` produces a file byte-identical (`cmp`) to the one produced by the same command on `main` at `3fd90514a4f650591343bb97f2011836ec1287cd`.
- Invalid dates give a clear error and no file: for each of `2026/03/01`, `2026-3-1`, `2026-02-30` and `abc`, passed as `--start` and again as `--end`, `rm -f /tmp/t004-bad.csv; python -m app.export_report /tmp/t004-bad.csv --start <value>` exits non-zero, prints to stderr a message containing the bad value and `YYYY-MM-DD`, and `/tmp/t004-bad.csv` does not exist afterwards (`test ! -e /tmp/t004-bad.csv`). An existing file at that path is left unchanged. Through the function, `export_csv(conn, path, start='2026-02-30')` raises `ValueError` and does not create the file.
- Start after end is an error: `rm -f /tmp/t004-bad.csv; python -m app.export_report /tmp/t004-bad.csv --start 2026-04-01 --end 2026-03-01` exits non-zero, prints to stderr a message saying the start date is after the end date, and `/tmp/t004-bad.csv` does not exist afterwards. The function raises `ValueError` for the same input.
- A valid range with no orders writes only the header: `python -m app.export_report /tmp/t004-empty.csv --start 2027-01-01 --end 2027-01-31` exits 0, prints `exported 0 rows to /tmp/t004-empty.csv`, and the file's bytes are exactly the UTF-8 BOM followed by `order_no,order_date,customer,city,amount\r\n`.
- Tests cover the cases above and full `pytest -q` passes.
- Exporting 10,000 orders still takes under 1 second (`python scripts/bench_export.py`).
